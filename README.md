# Pivot｜换场 · V1.1.5 功能快照

面向兼顾篮球和体能训练的业余爱好者。V1.1.3 在现有手机 PWA 加入动作库、三套场景模板、可调整的动作计划和多动作训练记录。动作说明、训练量和替换关系显示为待教练审核，本机预览用于体验操作。

## 从 GitHub 克隆后启动

在仓库根目录运行以下命令，打开 [训练页](http://127.0.0.1:8898/#training)。如果端口已被占用，可替换为其他空闲端口。数据写入本机的 `artifacts/`。

```sh
PIVOT_GUEST_MODE=1 PIVOT_CATALOG_PREVIEW=1 PIVOT_PUBLIC_ORIGIN= \
  python3 -B server.py --host 127.0.0.1 --port 8898 \
  --db artifacts/pivot.sqlite3 --rules-only
```

这条命令只需要 Python，可以体验模板、篮球记录、规则调整、确认开练及动作示范。模型意图识别和姿态计数依赖额外安装的本地运行环境，详见 [后端运行手册](BACKEND_RUNBOOK.md) 和 [第三方依赖](THIRD_PARTY_NOTICES.md)。

## 开发机启动

在本目录运行 `python3 ops/guest_access.py --local` 或双击 `启动新版手机MVP.command`，等服务启动后打开 [动作库预览](http://127.0.0.1:8897/#training)。服务在后台运行，访客状态独立存到 `~/Library/Application Support/Dee/Pivot-Demo-v113`。

每个浏览器通过随机 HttpOnly Cookie 获得独立 SQLite 和媒体目录。V1.1.3 延续现有的原生 JavaScript 手机 PWA 和 Python／SQLite 服务。

默认端口被其他服务占用时，可以用 `PIVOT_DEMO_PORT=8898 python3 ops/guest_access.py --local` 启动。启动器会返回实际入口，沿用同一数据目录。

## V1.1.3 篮球体能训练库

1. 从「训练 → 动作库」按八个类别浏览。搜索或打开「筛选」选择器械、场地和示范视频。动作详情显示条件、当前记录方式和已有示范。
2. 打开「居家弹力带全身」「健身房下肢与躯干」或「球场脚步与制动」，核对并编辑动作清单，确认保存到计划。
3. 练后逐项填写实际组次、负重、时间、距离或回合，再到「历史」核对。已保存的动作清单可继续交给 Pivot 调整。

当前范围见 [V1.1.5 版本说明](docs/RELEASE_V1.1.5.md)。

### 按计划开始和继续

在「训练」的「下一步训练」打开一套已保存的计划。按动作记录实际完成或跳过，返回后用「继续训练」恢复已保存的进度。结束时核对动作状态、填写实际总时长和感受，确认后到「历史」查看。

「本周训练与球局」可以快速记球。调整页会展示引用的实际篮球记录，偏累时先核对今天的状态。计划确认后可从回执去训练页开练。「球场脚步与制动」模板内五个动作均有可点开的自制动画，待体能教练审核。 [示范来源](web/assets/demos/SOURCES.md)

## V1.1.2 模型与规则

从「计划」用自然语言输入「今天只有 30 分钟，只有弹力带，状态正常」。当前候选或追问旁显示本轮处理来源。模型忙或无法完成解析时，保留输入和限制，用规则继续生成候选或追问。快捷入口按用户填写的条件继续。

诊断按访客保存来源、原因、重试次数和时间数据，保留 30 天。本地验收单独采集首请求模型成功比例和耗时，冷启动、模型就绪和复验分别记录。 [验收入口](docs/FRONTEND_NOTES.md#回归入口)

## 可操作流程

1. 「我的」维护已有计划的具体内容、目的、场地与器械，填写阶段目标期限、重要球类活动；维护本人认可的短时/低负荷备选。
2. 「计划」描述变化。系统查询档案、训练反馈和获授权的新鲜健康记录，补问必要条件，准备候选；明确确认后才写入，保存成功与训练完成独立。
3. 「设备」上传 Apple 健康 XML/ZIP 或规范 CSV/JSON。展示来源、采集时间、各项时效；关闭/重新开启引用或清除记录均可操作。
4. 「训练」选择深蹲、俯卧撑、弯举、侧平举或肩上推举，拍摄或上传视频。真实 RTMPose/YOLOX 提取关键点，按动作独立规则统计。回放骨架、人工校正后保存；不足时不给可靠总数。
5. 「历史」查看、修订、删除、导出实际训练；「我的 → 运动目标」维护训练日与动作目标、查看进度。

## 边界

- PWA不是上架的原生iOS应用。本版真实穿戴路径是**文件导入**；HealthKit原生授权、Garmin账号自动同步尚未实现。
- 本机 Qwen3-4B 负责结构化意图提取。候选资格、安全停止、版本检查和保存由规则约束，用户确认后才正式写入计划并生成回执。
- 视频支持0.3–45秒、60 MiB内、普通MP4/MOV/WebM，需单人、固定机位、关键关节可见。五动作具备各自路径，不代表在任意机位都能可靠计数；这是二维动作观察，不是姿态评分、康复判断或专项训练处方。
- 不确定保存结果按操作编号核对，避免重复写入。API与媒体不离线缓存。视频保存最多7天，可单独删除。
- 目前仅验证流程和有限样片，不声称真实用户留存、康复效果、运动表现改善或商业准确率。

UI与交互参考 Good-GYM（MIT）；姿态模型参考MMPose/RTMPose。QuickPose、OpenPose、EasyMocap为参考资料，未虚称全部接入。见 `THIRD_PARTY_NOTICES.md`。

## 2026-11-11 体验版升级

在现有 PWA 上增加 experience.js / experience.css，保留原 API、视频推理、导入与记录能力。仅对未修改的新访客空间加入标注清楚的力量训练＋周末篮球示例；不会覆盖已有用户档案、任务或训练记录。

首页直接发起「只有30分钟／临时约球／没睡好」，表单提供条件选项，已有规则生成候选；确认页固定操作栏提供保存或保留原计划。当前计划和实际反馈独立保存。示例反馈写入示例标记，状态示例未写入真实穿戴数据接口。自定义自然语言请求仍通过原模型解释与规则约束路径。

历史质量记录见 `tests/test_experience.cjs`、`tests/test_experience_edges.cjs` 和工作区 `output/Pivot-体验版升级-2026-11-11/screenshots`。
